# Clip Merger

An Android app for trimming and joining H.265/HEVC MP4 clips, such as those recorded by DJI action cameras.

- **Load** several MP4 files at once (Android's system file picker, multi-select).
- **Trim** each clip: scrub the preview, then tap *Set start here* / *Set end here*.
- **Order** the clips with ▲ / ▼ (they are added in file-name order, so DJI's numbered files start out in recording order).
- **Export** to a new MP4 file, either:
  - **Keep original codec (no re-encoding):** samples are copied byte-for-byte. Fast and lossless.
  - **Re-encode:** choose H.265 or H.264 (whichever this phone can encode), the resolution (same, 2160p, 1440p, 1080p, 720p) and the bitrate. Cuts are frame-accurate.

Exports keep running when you switch to another app or turn the screen off: they run in a foreground service
with a notification showing progress, the estimated time left, and a Cancel button. The app shows the same
estimate while it is open. On Android 13+ the app asks for permission to show notifications; if you decline,
exports still run in the background, but the progress notification is hidden.

Requires Android 8.0 (API 26) or newer.

## Install

Copy `clip-merger.apk` to the phone and open it (allow "Install unknown apps" for your file manager when asked).
It is signed with a debug key that is checked into `tools/debug.keystore`, so later builds from this repo install as updates.

## How it works

| | Keep original codec | Re-encode |
|---|---|---|
| Video | Compressed samples copied unchanged; the original `hvc1`/`hvcC` sample description is kept | Decoded with `MediaCodec`, drawn through OpenGL ES (scaling / letterboxing), encoded with `MediaCodec` |
| Audio | Copied unchanged | Copied unchanged |
| Cut accuracy | Each clip starts at the **keyframe at or before** the trim start (the trim screen shows where). The end can be up to a few frames early, because frames that depend on a frame after the end point have to be dropped. | Frame-accurate |
| Clips must match | Same codec, resolution and codec settings (e.g. all 4K/60 10-bit from the same camera mode) | Anything H.264/H.265; other sizes are letterboxed into the first clip's frame |

The app has its own MP4 reader and writer (`Mp4Source`, `Mp4Writer`) instead of Android's `MediaMuxer`. `MediaMuxer` writes 32-bit file offsets, which limits output to 4 GB, and DJI cameras already split recordings at about 4 GB. `Mp4Writer` uses 64-bit offsets (`co64`, 64-bit `mdat`), so the output size has no 4 GB limit.

## Limitations

- **Re-encoding outputs 8-bit SDR.** 10-bit sources (D-Log M, HLG) are decoded and re-encoded without tone mapping, so their colours will not match the original. Use *Keep original codec* to keep 10-bit/HDR footage untouched.
- If the clips' audio formats differ, the output has no audio (the app tells you). Clips without audio leave silent gaps.
- DJI's extra tracks (timecode, `djmd` telemetry) are not copied; only the first video and first audio track are.
- Files must be on device storage (or an SD card). Cloud-only documents that can't be opened for random access will fail.

## Building

### Without the Android SDK (what produced the APK in this repo)

```
tools/build_apk.sh            # writes clip-merger.apk
```

Needs JDK 17+ (tested with 21), Python 3 and `curl`. On first run it downloads three jars from Maven Central into `tools/cache/`:
the Android 14 framework classes (`org.robolectric:android-all`), the `dx` dexer and `apksig`.
The binary manifest is generated by `tools/axml.py`; the APK is signed with APK Signature Scheme v2.

### With Android Studio / Gradle

Open the project folder in Android Studio. `app/build.gradle.kts` uses AGP 8.5.2 with Gradle 8.9 and no external libraries.
(The Gradle build has not been run in the environment that produced this repo, which had no access to Google's Maven repository.)

## Testing status

- The MP4 reader/writer and the lossless merge were run on a desktop JVM against HEVC + AAC clips made with x265 (B-frames, open GOP, 8-bit and 10-bit):
  - Joining whole clips gives output whose every decoded frame is bit-identical to the source frames (840 of 840), with no decode errors in FFmpeg.
  - Trimmed joins start at the expected keyframes, and audio stays in sync at the joins (within one AAC frame).
  - Clips with different codec settings are refused with an explanation.
  - The `hvcC` box built for encoder output matches FFmpeg's field for field.
- The APK's manifest and v2 signature were checked with androguard and apksig.
- Version 1.0 was tested by the user on a phone: loading, trimming, ordering and both export modes work.
- Version 1.1 (background export via a foreground service, time-left estimate) has been compiled and its manifest checked, but not yet run on a phone.
